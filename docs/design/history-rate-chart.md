# llm-proxy 历史速率图设计

面向 MYS-1405：在既有 `/admin` 页面上新增「历史速率」趋势图，形态参考 lovdex 的
Token 统计页，目的是**评估上游 API 平台的稳定性**。

## 目标与非目标

**目标**

1. 在浏览器里看到每个模型随时间变化的 token / 请求速率、失败率与延迟。
2. 窗口可切 1 小时 / 6 小时 / 24 小时，切换后曲线量级可比。
3. 把「上游开始不稳」这件事变得可见：失败率从 0 开始爬、延迟抬升，要能一眼看出。
4. 页面仍然是一个自包含文档，不引入任何前端依赖与构建工具链。

**非目标**

- 不做跨重启的历史持久化（统计仍是进程内内存态，重启清零）。
- 不做按别名 / 按网关维度的分组（按上游模型名聚合，沿用既有口径）。
- 不改动任何请求路径的转发语义。

## 关键决策

### 1. 数据来源：在既有采集器里加第二只环形桶

既有 `stats.go` 已有一只 1800 槽的**秒级**环形桶，供「最近 60 秒 TPM/RPM」精确求和，
以及 30 分钟的迷你趋势图。它不够长，撑不起 24 小时视图。

做法是**并存**而不是替换：新增 `history [1440]historyMinute`，每个模型一分钟一个槽，
覆盖 24 小时。两者回答不同的问题——秒级桶给精确的当前值，分钟桶给长趋势——而且
**同一分钟的两种口径天然一致**：最新那个分钟桶累加的就是秒级桶在求的那批请求，
所以图表右端与页面上的 TPM/RPM 不会对不上（有测试守住这一点）。

每个分钟槽记 `{tokens, requests, failures, latencyMS, maxLatency}`。带上延迟是因为
「上游是不是变慢了」是这张图的一半用途；存累计值而不是平均值，前端要平均就除一下，
不必为不同窗口各存一份。

内存：128 个模型（既有上限）× 1440 槽 × 约 40B ≈ 7MB 上限，实际只会用到的模型数远小于此。

### 2. 窗口与桶长：桶长整除一小时

| 窗口 | 桶长 | 点数 |
|------|------|------|
| 1 小时 | 60 秒 | 60 |
| 6 小时 | 300 秒 | 72 |
| 24 小时 | 900 秒 | 96 |

三个桶长都整除 3600，所以横轴刻度永远落在整分钟上，不会因为「每格 7 分钟」这种
步长让钟点逐格漂移。点数都在 60–100 之间：够看出一次抖动，又够手写 SVG 一模型一条
路径而不卡。

**最新一桶是「进行中」的那一桶**：`end` 取下一个桶边界而不是当前时刻。否则最新点最多
会滞后一整个桶长（24 小时视图下就是 15 分钟），刚好把正在发生的故障藏起来。

桶内没有流量时返回**显式的零点**而不是跳过。前端一个桶画一个点，跳过空桶会把后面
所有点左移，整条曲线的时间就错位了。

比保留窗口更早的桶不参与计算；如果请求的窗口超出了进程实际看得到的范围（刚重启），
窗口被裁到实际有数据的那一段，而不是把看不见的时段报成「没有流量」。

### 3. 口径：四种，共用一份数据

| 口径 | 图形 | 纵轴 |
|------|------|------|
| Token 速率 | 堆叠面积 | 每分钟 token |
| 请求速率 | 堆叠面积 | 每分钟请求 |
| 失败率 | 叠加折线 | 0–100% 固定 |
| 平均延迟 | 叠加折线 | ms |

- 「量」可以堆叠，「率」不能（0.1% + 0.2% 不是 0.3% 的失败率），所以率走叠加折线。
- 后端给的是桶内总量，前端按桶长归一化到每分钟。不归一化的话切到 24 小时视图曲线会
  凭空涨 15 倍——那是桶变宽了，不是流量变了。
- 失败率纵轴固定 0–100%：自适应的话一次失败就把曲线顶满，「本来是 0」这件事就看不见了。

四种口径都由前端从同一份响应算出，所以切换口径**不触发请求**，只是重画。

### 4. 模型上限：超过 8 个合并为 (other)

一个模型一条线一种颜色，十几个就糊在一起了。按窗口内 token 降序取前 8 条，其余合并成
`(other)` 一条，并在图例里说明合并了几个。**区间合计仍然统计全部模型**，不因为折叠而
少算。响应另带 `all_models`，列出窗口内出现过的每个模型，供页面做筛选 chip。

### 5. 前端：手写 SVG，不引依赖

管理页面是 `go:embed` 的单文件，没有 npm、没有打包器，也不该为了画一张图去引 CDN——
它跑在可路由的地址上，外部资源既不可靠也是额外攻击面。所以图表是手写的 SVG：

- 堆叠面积用一条路径表示：上沿正着走，下沿倒着走，闭合。同一个 `buildAreaPath`
  传不同基线就能画线也能画带。
- 纵轴上限走 1/2/2.5/5/10 × 10ⁿ，刻度落在整数上。
- 横轴刻度按容器宽度取目标个数，步长吸附到**能整除点数的约数**上（否则最后一个刻度
  落不到时间轴末尾）；末尾刻度与前一个的像素距离容不下两个标签（各约 34px）时不补，
  宁可少一个刻度也不重叠。
- tooltip 用一条跟随鼠标的竖线 + 一个浮层，覆盖层是整块绘图区的透明矩形，不给每个
  数据点挂命中区。

### 6. 页面拆成两个源文件 + 一步内联

页面源码拆成 `admin.html`（结构 + 样式）与 `admin.js`（脚本），`build.sh` 把脚本内联成
单文件 `admin_page.html` 供 `go:embed`。

拆的理由只有一个：让图表的**纯计算**部分能在 node 下单测。`admin.js` 末尾用
`typeof document === "undefined"` 判断，在 node 下导出这些纯函数而不是启动页面，于是
归一化、堆叠基线、纵轴取整、刻度抽样、区间小结这些确定性逻辑都有单测。

代价是多了一步构建。为了不让它悄悄失败，`TestAdminPageIsUpToDateWithItsSources` 会
用同一份 `pagegen.Render` 重新生成一遍并与检入的 `admin_page.html` 比对，改了页面忘了
跑 `build.sh` 直接测试失败。

### 7. 历史请求独立于实时刷新

图表的轮询是 30 秒，独立于页面 5 秒一次的实时统计：24 小时视图变化慢，每 5 秒重取
96 个桶是浪费。窗口与口径是**前端状态**，不因为刷新被重置；暂停自动刷新时图表也停。

## 组件划分

| 文件 | 职责 | 依赖 |
|------|------|------|
| `stats_history.go` | 分钟环形桶、窗口查询与聚合、`(other)` 折叠 | 仅标准库 |
| `stats.go` | 在记录路径上同时写秒级桶与分钟桶 | — |
| `admin.go` | `/admin/api/stats/history` 路由与参数解析 | `stats_history.go` |

| `pagegen/` + `cmd/pagegen` | 把两者内联成 `admin_page.html` | — |

## 接口

```
GET /admin/api/stats/history?range=1h|6h|24h&model=<上游模型名>（可重复）
```

`range` 缺省或无法识别时按 24 小时处理（取值只来自页面自己的按钮，不必为此报错）；
`model` 最多取前 32 个，防止调用方用重复参数让服务端做无界的工作。

响应：

```json
{
  "range": "6h",
  "from": 1789995180, "to": 1789998780, "bucket_seconds": 300,
  "timestamps": [1789995180, 1789995480],
  "totals": {"requests": 40, "failures": 1, "tokens": 106383},
  "models": [
    {"model": "DeepSeek-Flash",
     "points": [{"ts": 1789995180, "tokens": 1200, "requests": 4, "failures": 0,
                 "latency_ms": 2400, "max_latency_ms": 900,
                 "failure_rate": 0, "avg_latency_ms": 600}]}
  ],
  "all_models": ["DeepSeek-Flash", "GLM-5.3"],
  "models_excluded": 0
}
```

`points` 与 `timestamps` 一一对应、长度相同（有测试守住），前端按索引直接对齐。
`(other)` 是折叠出来的最后一条，模型名字面上就是 `(other)`；`models_excluded` 说明被
折叠了几个。

## 错误处理

- 认证与未配置口令的行为与其余 `/admin*` 完全一致：401 / 404。
- 非 GET → 405。
- 无任何请求时返回空 `models` 与全零 totals，页面画「还没有请求经过代理」的空态，
  而不是让图表消失或报错。
- 图表请求失败时在图上留一条错误提示，不影响实时统计的显示。
